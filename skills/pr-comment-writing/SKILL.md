# Pull Request Comment Writing

A good comment helps the author understand a specific risk and decide what to do.

1. Point to a concrete line or behavior and describe the scenario that causes a problem.
2. Explain impact and severity without overstating certainty.
3. Suggest a focused fix or ask a precise question when context is missing.
4. Distinguish blocking defects from non-blocking suggestions and style preferences.
5. Avoid duplicating an existing thread; check nearby comments first.
6. Keep tone respectful, direct, and about the code rather than the person.
7. For summary reviews, lead with blockers and list verified strengths only when useful.

Do not post, resolve, or dismiss comments unless the user asked you to interact with GitHub. Do not reveal secrets or sensitive vulnerability details in public threads; follow private disclosure procedures when needed.
